上游站点连不上时（网络抖动、站点抽风），插件数着连续失败次数「熔断」： 期间请求不再发给上游干等，而是立刻回 429，让 Claude Code 这类 agent 按 它自带的退避策略自动重试；熔断窗口过后放行一个请求去试探，一通就恢复、 后续重试自动停止。整个过程不需要你盯着终端。

关掉后插件完全不介入（fail-open）
次 少则熔断得早，多则给上游更多机会自愈（1–10） 要填 1 到 10 之间的整数
秒 这期间请求一律秒回 429；之后每再失败一次窗口翻倍（5–300） 要填 5 到 300 之间的数（5 的倍数最整齐）
秒 翻倍到这一档就不再涨；agent 对 429 的耐心有限，别设太长（30–1800） 要填 30 到 1800 之间的数

边界：如果 agent 自己的重试也耗尽了、终端已经报错停下，那一轮对话任何插件 都救不回来，需要你手动重发。这个插件做的是让 agent 的耐心撑过更长的抖动。

隐私：熔断状态只是几个数字，记在 magpie 网关进程的内存里，不上盘、不发网、 不读你的对话内容。
